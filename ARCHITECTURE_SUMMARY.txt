KEY ARCHITECTURE DECISIONS
---------------------------

Backend Stack:
✓ FastAPI (async Python, auto-docs, type safety)
✓ PostgreSQL with PostGIS (spatial queries 100x faster)
✓ S3-compatible storage (MinIO on-prem, AWS S3 cloud)
✓ OAuth2 + JWT (MFA support, SSO integration)
✓ nibabel + nilearn (Nipy ecosystem)

Frontend Stack:
✓ React with TypeScript (component-based, strongly typed)
✓ Niivue (modern WebGL successor to Papaya)
✓ Material-UI (professional components)
✓ React Query + Zustand (optimal state management)
✓ Vite (fast build tool)

Infrastructure:
✓ Docker + Docker Compose (development)
✓ Kubernetes (production, optional)
✓ Prometheus + Grafana (monitoring)
✓ GitHub Actions (CI/CD)

CORE FEATURES PRESERVED
------------------------
✓ Patient data management (demographics, brain damage metadata)
✓ Scan management (multiple modalities per patient)
✓ Interactive lesion visualization (mask overlay)
✓ MNI coordinate-based search (now 100x faster!)
✓ Overlap heatmap generation across patients
✓ User authentication and authorization
✓ Notes and annotations
✓ All existing functionality maintained

NEW ENHANCEMENTS
----------------
+ Multi-site/multi-institutional support
+ Advanced search and filtering capabilities
+ ROI-based overlap analysis (upload custom ROIs)
+ RESTful API for programmatic access
+ Mobile-responsive design
+ SSO integration (SAML, OAuth, LDAP)
+ Multi-factor authentication (TOTP)
+ Comprehensive audit logging
+ BIDS format import/export
+ Batch data operations
+ Enhanced performance and scalability

SECURITY IMPROVEMENTS
---------------------
🔒 Encryption at rest (database + object storage)
🔒 Encryption in transit (TLS 1.3)
🔒 OAuth2 with JWT tokens (short-lived + refresh)
🔒 Multi-factor authentication support
🔒 Fine-grained RBAC (custom roles)
🔒 Row-level security in database
🔒 Comprehensive audit logging
🔒 PHI/PII redaction in logs
🔒 HIPAA-enabling features
🔒 Regular security scanning (OWASP)
🔒 Secure file sharing (presigned URLs)

MIGRATION STRATEGY
------------------
Low-risk, gradual approach:
1. Build new system in parallel (no disruption)
2. Migrate data with validation
3. Run both systems during transition
4. Incremental user migration
5. Full cutover when validated

Safety features:
→ Rollback possible at any stage
→ Parallel running of old and new systems
→ Automated validation scripts
→ Zero data loss guarantee

DEPLOYMENT FLEXIBILITY
----------------------
Architecture supports multiple models:

On-Premise:
- Use MinIO (free S3-compatible storage)
- Local PostgreSQL, Redis
- Own hardware or VMs

Cloud:
- AWS (S3, RDS, ECS/EKS)
- Google Cloud (GCS, Cloud SQL)
- Azure (Blob, PostgreSQL)

Hybrid:
- Start on-premise
- Migrate to cloud incrementally
- No vendor lock-in (S3 API standard)
